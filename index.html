Brand Guide

One visual language for every Faiz project. Soft frosted icons, a graphite and blue palette, and a calm, plain-spoken interface that behaves the same on every screen.

Version 1.0Light and darkOpen for public use

Principles

Four rules decide every design call. When two options both look fine, pick the one that follows these more closely.

Soft, not loud

Frosted graphite surfaces and generous space carry the interface. Nothing shouts.

Colour means something

Green confirms, red warns of loss, blue guides, yellow asks for attention. Never decoration.

Plain and direct

Short sentence-case labels, active verbs and one clear next step on every screen.

The same everywhere

One token set, one icon family and one voice across web, mobile and documentation.

Colour

A quiet graphite base, one blue for action, and a set of status and accent colours taken straight from the icon gradients.

Neutrals

Brand action

Blue is the only colour used for primary buttons, links, selected states and focus. One primary button per view.

Status

Each status has three roles: the base for icons and fills, the ink for text, and the tint for backgrounds. Never set text in the base colour.

Icon accents

Accents appear mostly inside icons. In interface chrome use them sparingly, for charts, tags and illustrations.

Contrast checks

PairRatioResult

Base status colours such as green #2f9e5b on white reach only 3.4:1. Use them for icons and large fills, and use the ink variants for any text.

Typography

Two families with clearly different jobs: Bricolage Grotesque gives headings their character, DM Sans keeps everything else easy to read.

Aa
Bricolage Grotesque

Display and headings. Weight 600 only, tracking -2% on large sizes. Fallback: Segoe UI, system-ui.

Aa
DM Sans

Body, labels, buttons and data. Weights 400 and 500. Use tabular numbers for tables and prices.

Type scale

Rules

Keep lines under 70 characters. Use sentence case everywhere, including buttons and headings. Use weight, size and space for hierarchy before reaching for colour. Never underline anything that is not a link.

Motion

Motion answers an action and never decorates. Hover lifts icons and tiles 3 px over 180 ms. Pressed buttons move down 1 px. Panels and menus open over 280 ms with the standard ease cubic-bezier(.2, .7, .2, 1). Only loading states may repeat. Everything stops when the system asks for reduced motion.

Icons

The Faiz icon family: soft frosted icons on a 64 px grid, lit from the top with a graphite gradient and a gentle drop shadow.

Anatomy

Fills use a vertical gradient from light to deep. Strokes are graphite #25272a with round caps and joins, 2.5 to 5 units thick. A 0.45 blur on the fill gives the frosted edge, and a soft shadow lifts each icon 3.5 units off the page. Neutral graphite is the default. Colour is added only for meaning.

Colour carries meaning

GreenCreate, confirm, secure
RedRemove, stop, destructive
BlueTransfer, inform, talk
Yellow and amberAttention, saved, special

Sizes

Filled buttons stay text-only so coloured icons never fight the fill. Never go below 20 px, where the frost blur starts to swallow detail. Use 24 px beside text, 32 px in navigation and toolbars, 48 px on cards, and 64 px for empty states and features.

Do and don't

Do

  • Pair icons with a text label unless the meaning is universal, such as Close or Search.
  • Keep one icon per meaning across the whole product.
  • Add an accessible name to icon-only buttons.
  • Leave at least 8 px of space around every icon.
  • In dark themes, set graphite icons on a Mist tile, because their ink is dark.

Don't

  • Recolour icons with CSS fill or filters. Pick the tinted version instead.
  • Stretch, rotate or add your own outlines and shadows.
  • Mix them with flat or outline icon sets.
  • Place two differently coloured icons side by side to mean the same thing.

Forms

Labels sit above fields and never disappear. Mark optional fields, not required ones. Validate when the person leaves a field, not while typing. Put the primary button at the end, aligned left on mobile and right on desktop, and keep Cancel beside it as a ghost button.

Writing

Write for the person using the product, not for the system underneath. Use sentence case, active verbs and the same name for an action from button to confirmation. Errors say what happened and how to fix it, and never apologise.

Accessibility

Accessible by default, to WCAG 2.2 AA.

ContrastText needs 4.5:1, large text and icon boundaries 3:1. Use the ink tokens for status text.
FocusEvery interactive element shows a 2 px ring in the focus colour with a 2 px offset. Never remove it.
TargetsAt least 40 px on desktop and 44 px on touch.
IconsDecorative icons are hidden from screen readers. Icon-only buttons carry an accessible name.
ColourNever use colour alone. Status always pairs an icon with text.
MotionHonour reduced motion. The tokens already set durations to zero.
ThemesLight and dark both ship with the tokens and follow the system setting.
